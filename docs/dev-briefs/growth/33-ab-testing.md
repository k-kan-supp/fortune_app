## ねらい

[M29](../monetization/29-paywall-placement.md)（壁の位置）、
[M27](../monetization/27-decoy-plan.md)（推奨プラン）、
[G31](31-fast-first-run.md)（入力項目）は、いずれも**議論では決まらない**。
測って決めるための仕組みを用意する。
ただし母数が小さいうちは A/B の結果は当てにならない。
その事実を仕組みに埋め込むことがこの指示書の要点。

## 実装

**backend**

- 実験定義を `app/services/experiment/` に置く。
  `GET /api/config` で「このユーザーはどの群か」を返す。
  **群の割り当てはサーバ側**で行い、ユーザー ID のハッシュで決定的にする。
  ランダムに毎回振ると同じ人が違う画面を見る。
- 未ログインユーザーは端末側の匿名 ID で割り当てる。
  登録後も同じ群に留まるよう、匿名 ID と ユーザー ID を紐づける。
- 実験の開始日・終了日・目標指標を定義に含める。
  **必要サンプル数を計算して記録する**。到達前に結論を出さない。
  「なんとなく良さそう」で止めると、以降の全ての判断が根拠を失う。
- 同時に走る実験は1つに絞る。相互作用を切り分けられない。

**frontend**

- 群の分岐は1か所（`hooks/useExperiment`）に集約する。
  各所で分岐を書くと、実験終了後の後片付けができなくなる。
- 実験終了後にコードから分岐を消す作業を、実験定義に紐づけて管理する。

## 検証

- 同一ユーザーが常に同じ群になること。
- 未ログイン→登録で群が変わらないこと。
- 群の分布が偏らないこと。
