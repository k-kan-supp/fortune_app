# G08 構造化データ

親: [集客戦略](../../growth.md) 視点8 ／ 関連: [G01](01-seo-free-tool.md) [G03](03-glossary-pages.md)

## ねらい

検索結果でのリッチな表示（FAQ の展開、パンくず）を狙う。
クリック率が上がるので、順位を上げるより手軽に流入が増えることがある。
ただし**実際にページに書かれていない内容を構造化データに入れると
スパム扱いになる**。ページの内容と一致させることが絶対条件。

## 実装

- JSON-LD で埋め込む。microdata は使わない（保守しにくい）。
- 種類ごとに対象ページを決める:
  - `BreadcrumbList`: 全ページ。[G07](07-internal-linking.md) の階層をそのまま使う。
  - `FAQPage`: 用語ページ（[G03](03-glossary-pages.md)）。「〜とは」の問答が自然に作れる。
  - `WebApplication`: トップの命式計算ツール。
  - `Article`: 干支・十神の記事（[G05](05-sexagenary-pages.md) [G06](06-ten-gods-pages.md)）。
- **生成はページ本文と同じデータから行う**。構造化データ用に別の文言を書かない。
  別々に管理すると、本文を直したときに構造化データだけ古くなる。
- `Person` や `Review` を捏造しない。存在しないレビューの星評価を入れる誘惑があるが、
  発覚すると検索評価に長期的な損害が出る。

## 検証

- 全ページの JSON-LD が構文的に妥当であること（ビルド時の検証）。
- FAQ の質問・回答がページ本文に実在すること（本文との突き合わせテスト）。
- パンくずのリンク先が全て有効であること。
- 検証ツール（Rich Results Test）で主要ページを確認し、結果を記録する。

## 完了条件

- [ ] JSON-LD が本文と同じデータから生成されている
- [ ] 構文検証がビルドに組み込まれている
- [ ] 実在しない情報を含んでいない
- [ ] `check.sh` 緑
