# G31 初回30秒

親: [集客戦略](../../growth.md) 視点31 ／ 関連: [G02](02-tool-landing.md) [G24](24-result-before-signup.md)

## ねらい

流入してから結果を見るまでを30秒以内にする。
ここが遅いと、[G01](01-seo-free-tool.md)〜[G20](20-referral-reward.md) で
どれだけ人を連れてきても穴の空いたバケツになる。
**入力項目を減らすことが最も効く**。項目が1つ増えるごとに完了率が落ちる。

## 実装

**frontend**

- `features/fortune/components/BirthInputForm.tsx` の必須項目を
  生年月日・時刻・性別の3つに固定する。それ以外は結果表示の後に聞く。
- 出生地を初期入力から外す。真太陽時の補正は精度上は正しいが、
  入力の摩擦に見合わない。既定値（東京）で計算し、
  結果画面で「出生地を指定するとより正確になります」と案内する。
- 時刻不明の選択肢を必ず用意する。出生時刻を知らない人は多く、
  ここで詰まると入力が完了しない。時刻不明時は時柱を除いた命式を出す。
  `app/schemas/fortune.py` で受け、`services/saju/pillars.py` に時柱なしの分岐を足す。
- 日付入力は数字キーボードが出る形式にする。
  ネイティブの日付ピッカーは年を遡るのに時間がかかる。年月日を直接入力させる方が速い。
- 送信後の待ち時間に何も表示しない状態を作らない。
  計算中の表示を入れる（結果の期待を高める演出としても機能する）。

**backend**

- `/api/fortune` の応答時間を計測（[G09](09-performance.md)）。
  10枚のチャート生成が遅いなら、まず無料区画だけ返して残りを遅延取得する。

## 検証

- 流入から結果表示までの時間を実機・実回線で計測して記録する。
- 入力完了率を [G32](32-funnel-analytics.md) で計測できること。
- 出生地未指定で結果が出ること。
- 時刻不明で命式が出ること（時柱以外が正しいこと）。
