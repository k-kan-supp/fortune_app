# G29 週次メール

親: [集客戦略](../../growth.md) 視点29 ／ 関連: [G26](26-push-timing.md) [M14](../monetization/14-lucky-day-calendar.md)

## ねらい

通知を切った人・アプリを開かなくなった人に届く最後の経路。
日次より**週次の方が読まれる**。「今週の流れ」は予定を立てる文脈と噛み合い、
[M14](../monetization/14-lucky-day-calendar.md) のカレンダーへの導線になる。
`backend/app/services/email/` が既にあるので、送信基盤は流用できる。

## 実装

**backend**

- `app/services/email/` に週次配信を追加。
  内容は `daily.py` の7日分（[M14](../monetization/14-lucky-day-calendar.md) の `range_reading()`）から
  「今週最も動く日」を抜き出す。全7日を羅列しない。読まれない。
- 配信は日曜夜か月曜朝。週の始まりに合わせる。
- **配信停止リンクを全メールに入れる**。1クリックで止まること。
  ログインを要求する停止導線は法令上も体験上も不適切。
- 開封・クリックの計測を入れるが、**トラッキングピクセルの利用を明記**する。
  プライバシーポリシーに記載のない計測をしない。
- バウンス処理を入れる。無効アドレスに送り続けると送信ドメインの評価が落ち、
  他のメール（認証メール等）も届かなくなる。ここが最も見落とされる。

**frontend**

- 配信設定を設定画面に。既定はオフにするか、登録時に選ばせる。
  勝手に配信を始めない。

## 検証

- 配信停止が1クリックで完了すること。
- バウンスしたアドレスが配信対象から外れること。
- 停止後に送信されないこと。
