# G24 登録前に結果を見せる

親: [集客戦略](../../growth.md) 視点24 ／ 関連: [G25](25-save-to-signup.md) [M01](../monetization/01-free-paid-line.md)

## ねらい

**着手順の上位3本の1つ**。登録を先に要求すると、
価値が伝わる前に大半が離脱する。命式を出すのに本来アカウントは要らない
（計算に必要なのは生年月日だけ）ので、技術的な制約ではなく設計の選択の問題。
先に価値を渡し、**保存したくなった時点**で登録を求める（[G25](25-save-to-signup.md)）。

## 実装

**backend**

- `/api/fortune` を認証不要のまま維持する。既にそうなっているなら、
  今後も認証を足さないことを明文化する。
- **レート制限を入れる**。認証不要の計算エンドポイントは
  そのままだと外部から叩かれ放題になる。IP ベースの制限を
  `app/core/middleware.py` に足す。制限値は実利用を妨げない水準にする。
- 未登録ユーザーの結果は一時的にサーバへ保存しない。
  クライアント側に持たせ、登録時に引き継ぐ。

**frontend**

- `pages/FortunePage.tsx` → `ResultPage.tsx` の遷移に認証を挟まない。
  `features/auth/components/RequireAuth.tsx` の適用範囲を確認し、
  結果表示の経路から外す。
- 未登録の結果を localStorage に保持し、登録完了時に
  [M23](../monetization/23-reading-history.md) の履歴へ引き継ぐ。
  **登録後に入力し直させない**。ここで再入力を求めると、そこで落ちる。

## 境界

**登録を求める瞬間と、その体験の設計は [G25](25-save-to-signup.md) が持つ**。
この指示書が決めるのは「どこまで登録を求めないか」という境界線の位置と、
そこまでを認証なしで通すための実装だけ。

## 検証

- 未認証で結果表示まで到達できること。
- 登録後に未登録時の結果が引き継がれること。
- レート制限が効くこと。

## 完了条件

- [ ] 未認証で命式が見られる
- [ ] 結果が登録時に引き継がれる
- [ ] レート制限がある
