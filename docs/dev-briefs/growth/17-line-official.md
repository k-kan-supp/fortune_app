# G17 LINE 公式

親: [集客戦略](../../growth.md) 視点17 ／ 関連: [G26](26-push-timing.md) [G29](29-weekly-email.md)

## ねらい

日本ではプッシュ通知より LINE の方が確実に届く。
アプリを入れていない層にも毎朝の運勢を配信でき、
**アプリ未インストールのまま日次習慣を作れる**のが最大の利点。
そこからアプリへ引き上げる。占いは LINE 公式アカウントとの相性が特に良いジャンル。

## 実装

**backend**

- `app/services/messaging/line.py` を新設。
  友だち追加時に生年月日を聞き、`services/saju/pillars.py` で命式を作って保存する。
  LINE のユーザー ID とアプリのユーザーを紐づける設計を最初に決める
  （後から統合するのは苦労する）。マイグレーション必須。
- 配信は `daily.py` の結果の**要約1行**まで。全文はアプリで、が原則。
  LINE で完結すると引き上げが起きない。
- **配信内容の生成と頻度上限は [G26](26-push-timing.md) の通知サービスが持つ**。
  この指示書は LINE というチャネルへの適応（友だち管理・応答・配信コスト）だけを持つ。
  同じ内容を [G26](26-push-timing.md) プッシュ / [G29](29-weekly-email.md) メール /
  [G28](28-home-widget.md) ウィジェットが別々に生成すると、文言がずれる。
- **配信数の上限に注意**。LINE 公式アカウントは無料枠を超えると従量課金で、
  友だちが増えるほどコストが増える。配信頻度は1日1回に固定し、
  友だち数と配信コストを [G38](38-cpa-guardrail.md) の枠組みで監視する。
- 応答メッセージ（「今日の運勢」と送ると返す）を用意する。
  プッシュだけでなく、ユーザーが取りに来る導線があると配信コストが下がる。
- ブロック・友だち解除の webhook を処理し、配信対象から確実に外す。

## 検証

- 友だち追加からの生年月日登録フローが完走すること。
- ブロック後に配信されないこと。
- 配信数が上限を超えないこと（送信前のチェック）。
