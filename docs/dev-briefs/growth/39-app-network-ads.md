# G39 アプリ面広告

親: [集客戦略](../../growth.md) 視点39 ／ 関連: [G40](40-aso.md) [G38](38-cpa-guardrail.md)

## ねらい

他のアプリの中に広告を出してインストールを取る。
Web アプリのままでは意味が薄いので、**[G40](40-aso.md) のアプリ化が前提**。
一般に CPA は検索広告より高く、質も低い。
[G36](36-search-ads.md) と [G37](37-meta-ads.md) で上限内に収まらなかった場合に、
初めて検討する順序で良い。

## 実装

**前提**

- ネイティブアプリが公開されていること（[G40](40-aso.md)）。
- CPA 上限（[G38](38-cpa-guardrail.md)）が決まっていること。

**開発側**

- インストール計測（アトリビューション）の SDK を入れる。
  どの広告経由でインストールされたかが分からないと、出稿の良し悪しが判断できない。
- **ディープリンク**を実装する。広告からインストールした人を、
  広告の訴求内容に対応する画面に直接着地させる。トップに落とすと転換が落ちる。
- インストール直後のオンボーディングを [G31](31-fast-first-run.md) と同じ規律で作る。
  広告経由のユーザーは目的意識が薄いので、初回体験の速さがさらに重要。
- アトリビューション SDK が送るデータを確認する。
  [G34](34-analytics-foundation.md) の規律（個人特定情報を渡さない）を適用する。

**運用**

- 不正インストール（ボット）に注意。CPA が異様に安い出稿先は疑う。

## 検証

- ディープリンクが正しい画面に着地すること。
- インストール元が計測できること。
- SDK が命式・生年月日を送出しないこと。

## 完了条件

- [ ] アプリが公開されている
- [ ] ディープリンクが動く
- [ ] 送出データが検証済み
- [ ] `check.sh` 緑
