# G04 生年月日別ページ

親: [集客戦略](../../growth.md) 視点4 ／ 関連: [G05](05-sexagenary-pages.md) [G09](09-performance.md)

## ねらい

「1990年5月3日 生まれ 性格」のような検索を取りにいく。
日付ごとにページを作れば理論上は膨大なページが作れるが、
**中身が薄いページの大量生成は検索評価を下げる**。ここが最大の判断点で、
無制限に生成しない設計にすることがこの指示書の主眼。

## 実装

**方針**

- 全日付（100年分 = 36,500 ページ）を生成しない。以下に絞る:
  - 過去60年分の日付に限定（現実的な検索需要のある範囲）
  - 1ページあたり、その日の日柱・月柱・年柱＋十神＋十二運の**実質的な解説**を載せる
  - 出生時刻で変わる部分は「時刻によって変わる」と明示し、アプリへ誘導する
- 生成せずに**オンデマンドでレンダリング＋キャッシュ**する案も検討する。
  ビルド時間が現実的でなくなるなら、こちらが正解。
  命式計算は軽いので、初回アクセス時に生成してキャッシュする方が運用が楽。

**実装**

- ルートは `/birth/{yyyy-mm-dd}`。
- 各ページに同日生まれの有名人（[G05](05-sexagenary-pages.md) と共通のデータ）があれば載せる。
  無ければ載せない。空欄のセクションを置かない。
- sitemap を分割して出力する（1ファイル50,000 URL 上限）。

## 検証

- 生成/レンダリングされたページに実質的な内容があること（文字数の下限チェック）。
- ビルドまたは初回レスポンスの時間を計測して記録する。
- sitemap が正しく分割されること。
- 存在しない日付（2月30日など）で 404 になること。
