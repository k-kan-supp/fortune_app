# G35 コホート分析

親: [集客戦略](../../growth.md) 視点35 ／ 関連: [G34](34-analytics-foundation.md) [G38](38-cpa-guardrail.md)

## ねらい

「今月のアクティブユーザー数」だけを見ていると、
新規が積み上がっている間は問題が見えず、伸びが止まった瞬間に崩れる。
**いつ入ったユーザーが、何日後まで残っているか**を登録月別に追う。
これが LTV（[G38](38-cpa-guardrail.md)）の根拠になり、広告を買えるかどうかを決める。

## 実装

**backend**

- `app/services/analytics/cohort.py`。登録日を起点に、
  D1 / D7 / D30 / D90 の残存率を出す。
- 「残存」の定義を1つに決める。**日次の運勢を開いた日**を採用する。
  ログインしただけを残存にすると数字が甘くなる。
  定義を後から変えると過去と比較できなくなるので、決めたら文書に残す。
- 分解軸は流入元（[G32](32-funnel-analytics.md) と共通）とプラン。
  流入元別に残存率が大きく違うのが普通で、これが広告の出し先を決める。
- 集計は [M49](../monetization/49-aggregate-reports.md) の k-匿名性の枠組みを共有する。
  社内向けでも個人が特定できる粒度まで下ろさない習慣を作る。

**運用**

- 見る頻度を決める。週次で十分。日次で見ても揺らぎしか分からない。

## 検証

- 残存率が100%を超えないこと（重複カウントの検出）。
- 登録月の境界（月末登録）が正しく扱われること。
- 流入元別の合計が全体と一致すること。
