# G45 占い館提携

親: [集客戦略](../../growth.md) 視点45 ／ 関連: [M38](../monetization/38-reader-referral.md) [G19](19-influencer-program.md)

## ねらい

対面の占い館と相互送客する。
アプリ → 対面は [M38](../monetization/38-reader-referral.md)、
対面 → アプリがこの指示書。占い館の来店客は**既に占いに金を払う人**で、
獲得後の課金率が一般流入より格段に高い。
占い師側にも、鑑定の準備時間が短縮されるという実利がある。

## 実装

**開発側**

- 鑑定士向けの命式管理機能（複数顧客の管理・比較・メモ）は
  **[G19](19-influencer-program.md) が実装する。ここでは作らない**。
  提携の実質的な対価はその機能だが、二重に仕様を書くと二重に実装される。
  この指示書が持つのは**店舗という場に固有の要件**だけ。
- 来店客向けの持ち帰り導線: 鑑定後に QR コードを渡し、
  スマホで自分の命式を開ける。**その場でアプリを入れさせない**。
  Web で開ける状態（[G24](24-result-before-signup.md)）が前提。
- 店舗ごとの紹介コード（[G20](20-referral-reward.md) の仕組みを流用）で成果を追う。
- 印刷して渡せる形（[M24](../monetization/24-pdf-export.md)）があると喜ばれる。

**注意**

- 来店客のデータを店舗が保持することになる。
  [G19](19-influencer-program.md) と同じ規律（保存上限・削除経路）を適用する。
- 自動鑑定が占い師の仕事を奪う形に見えると提携が進まない。
  「下準備を速くする道具」という位置づけを明確にする。

## 検証

- QR から命式が開けること（ログイン不要）。
- 店舗別の紹介成果が計測できること。
- 店舗アカウント間でデータが混ざらないこと。
