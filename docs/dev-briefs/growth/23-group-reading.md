# G23 グループ診断

親: [集客戦略](../../growth.md) 視点23 ／ 関連: [M21](../monetization/21-family-compatibility.md) [G21](21-partner-birthdate-invite.md)

## ねらい

3人以上の相性を一度に見る。友人グループ・家族・チームが対象で、
**1回の投入で複数人を連れてくる**のが利点。
[G21](21-partner-birthdate-invite.md) が1対1なら、こちらは1対N。
「グループで盛り上がる」文脈は、恋愛に興味が無い層にも届く数少ない導線。

## 実装

**backend**

- `compatibility.py` の2者比較を N 者に拡張する。
  **総当たりの計算量に注意**。N人なら N(N-1)/2 通り。上限を設ける（例: 8人）。
  上限なしにすると1リクエストでサーバが詰まる。
- 出力は「全体の傾向」＋「特に噛み合う組」＋「気をつける組」。
  **全ペアのスコア一覧を出さない**。誰と誰の相性が悪いかが名指しで並ぶと、
  グループの人間関係を壊す。これは実装で防ぐ（低スコアのペアを名指しで列挙しない）。
- 参加は [G21](21-partner-birthdate-invite.md) の生年月日リンクを流用する。
  1つのグループ URL に複数人が回答する形。新しい招待基盤を作らない。
- グループデータの保持期限を設ける（30日）。永続の名簿にしない。

**frontend**

- グループ内の役割（「まとめ役」「盛り上げ役」）のような、
  角の立たない見せ方にする。順位付けをしない。
- ja/en 同時。

## 検証

- 人数上限を超えたリクエストが拒否されること。
- 低スコアのペアが名指しで表示されないこと。
- 保持期限後にグループが消えること。
- `test_compatibility.py` の既存期待値が変わらないこと。
