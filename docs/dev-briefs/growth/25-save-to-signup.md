# G25 保存で会員化

親: [集客戦略](../../growth.md) 視点25 ／ 関連: [G24](24-result-before-signup.md) [M23](../monetization/23-reading-history.md)

## ねらい

[G24](24-result-before-signup.md) の続き。結果を見せた後、
**どのタイミングで登録を求めるか**。答えは「保存したくなった時」で、
具体的には「家族の命式も見たい」「後でまた見たい」と思った瞬間。
機能の制約として登録を課すのではなく、ユーザーの目的に登録が必要な状態を作る。

## 実装

**frontend**

- 登録を求める場面を限定する。以下だけにする:
  - 鑑定を保存する（[M23](../monetization/23-reading-history.md)）
  - 2件目以降の命式を作る
  - 日次の運勢を受け取る（通知が要るため）
  - マッチング機能を使う
  結果を見るだけなら最後まで登録不要（[G24](24-result-before-signup.md)）。
- 登録フォームを短くする。`features/auth/components/RegisterForm.tsx` の
  必須項目を最小にする。生年月日は既に入力済みなので**再度聞かない**。
  ここで同じことを2回聞くと、それだけで離脱する。
- 登録直後に元の画面へ戻す。トップに飛ばさない。
  何をしようとしていたかを保持して、そのまま完了させる。

**backend**

- メール確認（`VerifyPage.tsx`）を登録の**後**に回す。
  確認前でも基本機能を使えるようにし、確認が必要な機能だけを制限する。
  確認を待たせると、その間に離脱する。

## 検証

- 登録前後で生年月日の再入力が発生しないこと。
- 登録後に元の操作が継続されること。
- メール未確認で基本機能が使えること。

- [ ] 生年月日を二度聞かない
