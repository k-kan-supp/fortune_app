# G21 相手の生年月日を招待に変える

親: [集客戦略](../../growth.md) 視点21 ／ 関連: [M15](../monetization/15-pair-compatibility-detail.md) [G20](20-referral-reward.md)

## ねらい

**G シリーズで最も費用対効果が高い1本**。
相性判定は相手の生年月日を必要とする。多くの場合ユーザーはそれを知らない。
今は「知らないから諦める」で終わっているが、
ここを「相手に聞く導線」に変えると、**機能の必然がそのまま招待になる**。
広告と違い、止めても効き続ける。

## 実装

**backend**

- 「生年月日を教えてほしい」リンクを発行する。
  `app/models/birthdate_request.py`。`requester_id` / `token` / `answered_at` / `expires_at`。マイグレーション必須。
- 受け取った側は生年月日を入力するだけ。**登録不要**にする。
  登録を要求すると回答率が落ち、この施策の意味が消える。
- 回答後に「あなたも相性を見る」を出す。ここで初めて登録に誘う
  （[G24](24-result-before-signup.md) と同じ順序）。
- 回答された生年月日の扱い:
  - 依頼者に見せるのは**相性結果のみ**。生年月日そのものを表示しない。
    「相性を口実に生年月日を集める」道具にしない。ここは実装で担保する。
  - 回答者が後から取り消せるようにする。
  - 有効期限を短く（7日）する。

**frontend**

- 依頼リンクの送信は既存のメッセージアプリに委ねる（共有 API）。
- 回答画面は1画面で完結。説明を長くしない。

## 検証

- 依頼者の画面に相手の生年月日が表示されないこと（**最重要**）。
- 未登録で回答できること。
- 取り消しで相性結果も見えなくなること。
- 期限切れリンクが使えないこと。

## 完了条件

- [ ] 生年月日が依頼者に開示されない
- [ ] 登録不要で回答できる
- [ ] 回答者が取り消せる
- [ ] `check.sh` 緑
