# G42 PR・メディア

親: [集客戦略](../../growth.md) 視点42 ／ 関連: [M49](../monetization/49-aggregate-reports.md) [G47](47-new-year-season.md)

## ねらい

メディア掲載は広告費がかからず、被リンクとして [G01](01-seo-free-tool.md) にも効く。
ただし「占いアプリを作りました」ではニュースにならない。
**このプロダクトが持っているデータと技術**をネタにする。
`sxtwl` による天文計算ベースの節気（[G30](30-solar-term-alerts.md)）や、
統計（[M49](../monetization/49-aggregate-reports.md)）は他社が出せない切り口になる。

## 実装

**開発側が用意するもの**

- [M49](../monetization/49-aggregate-reports.md) の集計基盤を使い、
  発表可能な統計を出す。「日干別のマッチング成立率」「相性が高い干支の組み合わせ」など。
  **k-匿名性の制約を必ず通す**。プレスリリースに個人が特定できる数字を出さない。
- 記者が触れるデモ環境を用意する。ログイン不要で命式が出る状態
  （[G24](24-result-before-signup.md)）が既にあれば、それがそのままデモになる。
- プレスキット（ロゴ、スクリーンショット、事実関係のまとめ）を
  `docs/press/` に置き、更新の責任を明確にする。
- 掲載後の流入増に耐えられるか確認する。[G09](09-performance.md) の計測が前提。
  掲載された日に落ちるのが最悪の結末。

**やらないこと**

- 数字を盛らない。ユーザー数や精度の誇張は、後で必ず問題になる。

## 検証

- 発表する統計が k-匿名性を満たすこと。
- 掲載時の想定流入で応答が劣化しないこと（負荷試験）。
- プレスキットの記載内容が現状と一致すること。
