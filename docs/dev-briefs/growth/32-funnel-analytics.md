# G32 離脱点の計測

親: [集客戦略](../../growth.md) 視点32 ／ 関連: [G34](34-analytics-foundation.md) [G31](31-fast-first-run.md)

## ねらい

どこで人が消えているかを特定する。
勘で改善すると、実際には問題でない箇所を直し続けることになる。
[G34](34-analytics-foundation.md) の基盤の上で、
**最初に見るべき1本のファネル**を定義するのがこの指示書。

## 実装

主ファネルを1本に決める。増やすと見なくなる:

```
流入 → 入力開始 → 入力完了 → 結果表示 → 有料提示 → 購入
```

- 各段階のイベント名を確定し、[G34](34-analytics-foundation.md) の定義に登録する。
  イベント名を後から変えると過去データと繋がらない。**最初に決めきる**。
- 段階ごとに分解軸を1つだけ持つ: 流入元（[G36](36-search-ads.md) 等の
  パラメータ）。軸を増やすと母数が割れて判断できなくなる。
- 入力完了の段階は、**項目ごとの脱落**も取る。
  どの入力項目で止まっているかが分かると [G31](31-fast-first-run.md) の判断ができる。
- 結果表示 → 有料提示の間にスクロール深度を取る。
  [M29](../monetization/29-paywall-placement.md) の壁位置の判断材料になる。
  これが無いと壁を動かしても良し悪しが分からない。

**実装場所**

- フロントの計測は1つのフックにまとめる（`hooks/` に `useTracking`）。
  各コンポーネントで直接送信しない。送信漏れと重複が必ず起きる。

## 検証

- 各段階のイベントが1回ずつ送られること（重複が無いこと）。
- 流入元パラメータが最後まで保持されること。
- 段階の数値が単調減少すること（後段が前段を上回ったら計測が壊れている）。
