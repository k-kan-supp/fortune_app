# G12 OGP 自動生成

親: [集客戦略](../../growth.md) 視点12 ／ 関連: [G11](11-share-card-image.md) [G04](04-birthdate-pages.md)

## ねらい

SNS に URL が貼られたときのカード表示。
[G11](11-share-card-image.md) が「ユーザーが能動的に画像を保存して貼る」のに対し、
こちらは**URL を貼っただけで画像が付く**。摩擦がゼロなので拡散量が桁違いになる。
G03〜G06 で作った数百ページ全てに効くのも大きい。

## 実装

**backend**

- `app/api/routes/og.py` に `GET /og/{type}/{key}.png` を追加。
  [G11](11-share-card-image.md) の `share/card.py` を再利用する。新規に描画コードを書かない。
- 種類ごとにテンプレートを持つ:
  - 用語ページ（[G03](03-glossary-pages.md)）: 用語名＋一行説明
  - 干支ページ（[G05](05-sexagenary-pages.md)）: 干支＋特徴のキーワード
  - 結果ページ: レーダー図（[G11](11-share-card-image.md) と同じ）
- **CDN でキャッシュする**。SNS のクローラは一度に大量にアクセスしてくる。
  都度生成すると落ちる。生成済みを返すだけの状態にする。
- 結果ページの OGP は、その人の命式を含む URL を貼られる前提になる。
  URL に生年月日が含まれる設計なら、**貼った時点で生年月日が公開される**。
  短いトークン経由にして、URL から生年月日が読めないようにする。

**frontend**

- 各ページの `<head>` に `og:image` / `og:title` / `og:description` / `twitter:card`。
  [G01](01-seo-free-tool.md) の静的生成に含める。

## 検証

- 主要ページ種別ごとに実際の SNS でカード表示を確認し、結果を記録する。
- URL から生年月日が読み取れないこと。
- 大量同時アクセス時に生成が詰まらないこと（キャッシュの確認）。

## 完了条件

- [ ] 全ページ種別に OGP がある
- [ ] URL に生年月日が露出しない
- [ ] キャッシュされている
