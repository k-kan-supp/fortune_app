# G27 連続ログイン

親: [集客戦略](../../growth.md) 視点27 ／ 関連: [G26](26-push-timing.md) [M04](../monetization/04-ticket-credits.md)

## ねらい

連続日数を可視化して習慣化を促す。日次の運勢（[M02](../monetization/02-subscription-daily.md)）と
噛み合うが、**やりすぎると義務になる**。
「途切れると損をする」設計は短期の指標を上げるが、
途切れた瞬間に完全離脱を招く。緩い設計にする。

## 実装

**backend**

- `app/models/streak.py`。`user_id` / `current` / `longest` / `last_seen_date`。マイグレーション必須。
- 判定は JST の日付単位。24時間ロールにしない（何時までか分からない設計は不親切）。
- **1日の猶予を入れる**。1日空いてもリセットせず、2日空いたらリセットする。
  完璧な連続を要求しない。ここが「義務にしない」ための最重要点。
- 報酬は控えめに。7日で [M04](../monetization/04-ticket-credits.md) のチケット1枚程度。
  報酬を厚くすると、報酬目的の空ログインが増えて指標が嘘になる。
- 途切れた時に通知しない。「連続が途切れました」は最も嫌われる通知で、
  アンインストールの引き金になる。

**frontend**

- 表示は控えめに。画面を占有しない。
- 最長記録を残す。現在の連続が途切れても、積み上げたものが消えない見せ方にする。
- ja/en 同時。

## 検証

- 1日の猶予が効くこと（1日空き→維持、2日空き→リセット）。
- JST の日付境界。
- 同日の複数回ログインで連続日数が増えないこと。

- [ ] 途切れ通知を送らない
