# G20 招待リワード

親: [集客戦略](../../growth.md) 視点20 ／ 関連: [G21](21-partner-birthdate-invite.md) [M04](../monetization/04-ticket-credits.md)

## ねらい

招待した側・された側の双方にチケット（[M04](../monetization/04-ticket-credits.md)）を配る。
このプロダクトでは**招待の動機が既に機能に埋め込まれている**
（相性は相手が要る、[G21](21-partner-birthdate-invite.md)）ので、
リワードは動機を作るのではなく**後押しする**役割。だから報酬は控えめで足りる。

## 実装

**backend**

- `app/models/referral.py`。`inviter_id` / `code` / `invitee_id` / `rewarded_at`。マイグレーション必須。
- 報酬は [M04](../monetization/04-ticket-credits.md) の台帳に `reason="referral"` で付与。
  専用の報酬概念を作らない。
- **不正対策を最初から入れる**。ここを後回しにすると必ず悪用される:
  - 同一端末・同一 IP からの連鎖招待を検出して報酬を保留する
  - 招待された側が実際にアプリを使った（命式を1回出した）時点で報酬を確定する。
    登録直後に払わない
  - 1人あたりの招待報酬に上限を設ける
- 招待コードは推測不能にする。連番にしない。

**frontend**

- 招待画面は相性を見た直後に出す。文脈が最も強いタイミング。
- 招待の進捗（何人が登録し、何人が使ったか）を見せる。
  払われた報酬だけを見せると、保留中の分が不透明に見える。
- ja/en 同時。

## 検証

- 自己招待（同一人物の別アカウント）が報酬に繋がらないこと。
- 招待上限が効くこと。
- 未利用の招待に報酬が払われないこと。
