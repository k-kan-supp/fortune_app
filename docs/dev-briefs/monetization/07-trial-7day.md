# M07 7日間トライアル

親: [マネタイズ設計](../../monetization.md) 視点7 ／ 関連: [M02](02-subscription-daily.md) [G26](../growth/26-push-timing.md)

## ねらい

日次の運勢（[M02](02-subscription-daily.md)）は1日見ても価値が分からない。
**7日連続で当たっている感覚**が出て初めて継続に転ぶので、無料枠ではなく期間で配る。
狙いは「7日目までに何回開かせるか」であって、体験機能の多さではない。

## ねらいを外す典型

初日に全部見せて放置 → 3日目に忘れられて失効。これを防ぐのが実装の主眼。

## 実装

**backend**

- `subscription` に `trial_end` を追加（[M02](02-subscription-daily.md) のモデル）。マイグレーション必須。
- `entitlement.py`（[M05](05-hybrid-billing.md)）で `trial_end > now` を `active` と同等に扱う。
  判定を増やすのではなく既存の1か所に足す。
- トライアル開始・3日目・6日目・失効当日に通知を出すため、
  `app/services/notification/` に予約を積む。6日目の通知が最も転換に効くので必ず入れる。
- クレジットカード事前登録は**求めない**。登録要求で開始率が大きく落ちる。

**frontend**

- 残り日数を日次画面に常時表示（`DailyFortune.tsx`）。
- 失効後は直近7日分を「見た記録」として残し、再加入で復活すると明示する。
  ゼロに戻す UI にすると再加入率が落ちる。
- ja/en 同時。

## 検証

- `trial_end` 当日・翌日の境界テスト（タイムゾーンは JST 固定で確認）。
- トライアル中に有料化した場合、期間が二重に伸びないこと。
