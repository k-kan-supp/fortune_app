# M09 ペア割

親: [マネタイズ設計](../../monetization.md) 視点9 ／ 関連: [G22](../growth/22-couple-invite.md) [M15](15-pair-compatibility-detail.md)

## ねらい

2人同時加入で割引する。単なる値引きではなく、**相手を誘う理由**を課金に埋め込む施策で、
[G22](../growth/22-couple-invite.md) と表裏。相性は1人では完成しないので、
このプロダクトではペア割が値引き以上の意味を持つ。解約も2人分まとめて起きるリスクがある点に注意。

## 実装

**backend**

- `app/models/subscription.py` に `pair_id`（自己参照のグループ ID）を追加。マイグレーション必須。
- 成立条件は「招待者が加入済み」かつ「被招待者が招待リンク経由で加入」。
  招待は `app/services/auth/` の既存トークン発行を再利用し、新しいトークン基盤を作らない。
- 片方が解約したとき、残る側を通常価格に自動で戻さない。
  次の更新日から通常価格に移行し、その旨を事前通知する。無断値上げは苦情になる。
- 割引は決済プロバイダのクーポンで表現し、自前で金額計算しない。整合が崩れる。

**frontend**

- `pages/MatchesPage.tsx` / `ChatPage.tsx` からペア加入に誘導する。
  マッチ済みの相手がいる文脈でしか刺さらないので、汎用のプラン画面には置かない。
- 招待中・成立・解消の3状態を明示。宙ぶらりんの状態を作らない。
- ja/en 同時。

## 検証

- 招待の二重使用（同じリンクで3人目）が弾かれること。
- 片方解約時、もう片方の権限が期間末まで維持されること。
- `pair_id` が片方削除時に孤児にならないこと。

## 完了条件

- [ ] 招待リンクが1回しか成立しない
- [ ] 片方解約でもう片方が即時停止しない
- [ ] 値上げ前に通知が出る
- [ ] `check.sh` 緑
