# M14 開運日カレンダー

親: [マネタイズ設計](../../monetization.md) 視点14 ／ 関連: [M02](02-subscription-daily.md) [G30](../growth/30-solar-term-alerts.md)

## ねらい

`daily.py` は今日1日しか返さない。これを**先30日分**に広げてカレンダーにする。
「来週の水曜に商談を入れる」のような実用に耐えると、日次サブスク
（[M02](02-subscription-daily.md)）の解約理由が消える。予定アプリ的な使われ方が定着すると強い。

## 実装

**backend**

- `app/services/saju/daily.py` に `range_reading(pillars, start, days)` を追加。
  1日分の計算を日数分回すだけにし、**日次ロジックを二重に持たない**。
  ここを別実装にすると、今日の表示とカレンダーの表示がずれて信用を失う。
- 30日分の計算コストを測る。重いなら日付をキーにキャッシュする。
  命式は不変なので、`(subject_hash, date)` でキャッシュが素直に効く。
- 無料層は7日、加入者は30日。日数の出し分けはルート層で行う。
- 領域（仕事・対人・金銭・健康）ごとに良し悪しが違うので、
  日単位で1つの点数に潰さない。潰すと当たらなくなる。

**frontend**

- 月カレンダー表示。各日に4領域の記号を小さく置く。色だけで示すと色覚差で読めない。
- 予定を入れたい領域でフィルタできるようにする。
- ja/en 同時。曜日と月名のロケール差に注意。

## 検証

- `test_daily.py`: 同じ日付を単日 API とカレンダーで引いて**完全一致**すること。
- 月またぎ・年またぎ・節入りをまたぐ範囲。
- 30日分のレスポンスサイズと生成時間を計測して記録する。
