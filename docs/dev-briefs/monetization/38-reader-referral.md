# M38 占い師への送客

親: [マネタイズ設計](../../monetization.md) 視点38 ／ 関連: [M39](39-reader-marketplace.md) [M41](41-live-events.md)

## ねらい

アプリの自動鑑定で満足しない層 ──「もっと具体的に相談したい」という
最も支払い意欲の高い層 ── を、提携する占い師の対面/オンライン鑑定に送る。
自動鑑定と競合せず補完する。[M39](39-reader-marketplace.md) の前段階として、
まず少数の提携先への送客で需要を測る。

## 実装

**backend**

- `app/services/commerce/referral.py`。提携先ごとの送客リンクと成果計測。
- **送客時に命式データを外部に渡さない**。ユーザーが自分で提携先に情報を入力する形にする。
  「命式を引き継げて便利」より、第三者提供にあたる設計を避けることを優先する。
  どうしても引き継ぐなら、ユーザーの明示同意画面を挟み、何を渡すかを列挙して表示する。
- 成果は提携先からの報告ベース。自前で成約を追わない。
- 送客先の一覧・有効/無効は設定で切り替える。提携終了時にコード改修が要らないように。

**frontend**

- 出す場所は鑑定を読み終えた直後。読む前に出すと自動鑑定の価値を自分で下げる。
- 「アプリの鑑定とは別料金」であることを明示。
- 提携である旨（[M37](37-affiliate-goods.md) と同じ表示規律）を必ず添える。
- ja/en 同時。

## 検証

- 同意なしに生年月日が外部リンクのパラメータに乗らないこと。
- 提携先を無効化したら即座に非表示になること。
- 表示ラベルが省略できないこと。

## 完了条件

- [ ] 明示同意なしに個人データを渡さない
- [ ] 提携先の有効/無効が設定で切り替わる
- [ ] 別料金であることが明示されている
- [ ] `check.sh` 緑
