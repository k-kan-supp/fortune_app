# M24 PDF 出力

親: [マネタイズ設計](../../monetization.md) 視点24 ／ 関連: [M03](03-one-off-report.md) [M25](25-print-fulfillment.md)

## ねらい

同じ内容でも「PDF になっている」だけで支払い意欲が上がる。
鑑定書（[M03](03-one-off-report.md)）の実体を PDF にすると、
買った感触が出て、製本（[M25](25-print-fulfillment.md)）への足がかりにもなる。
画面のスクショではなく、印刷を前提とした組版にすることが価値の全て。

## 実装

**backend**

- `app/services/report/pdf.py` を新設。生成はサーバ側で行う。
  フロント生成にすると日本語フォントの埋め込みと再現性で必ず詰まる。
- 日本語フォントを**ライセンスを確認した上で**同梱する。
  埋め込み可否のライセンス条項を確認し、出典を README に記載する。ここは省略しない。
- 縦組みは狙わない。命式表とレーダー図が入るので横組みで良い。
- レーダー図はサーバ側で SVG を生成して埋める。フロントの `RadarChart.tsx` と
  **同じ軸順・同じスケール**になるよう、描画パラメータを共有の定数から取る。
  ここがずれると「画面と違う」という苦情になる。
- 生成は非同期にし、完了後にダウンロードリンクを出す。同期生成はタイムアウトする。

**frontend**

- 生成中の状態表示。完了後は `uploads/` 相当の保護された経路から配信する。
  署名付き URL にし、URL を知っていれば誰でも取れる状態にしない。

## 検証

- 日本語（漢字・かな）が欠落せずに埋め込まれること。
- 画面のレーダーと PDF のレーダーが同じ形になること。
- 未購入ユーザーが URL 直打ちで取得できないこと。
