# M06 初回無料枠

親: [マネタイズ設計](../../monetization.md) 視点6 ／ 関連: [M15](15-pair-compatibility-detail.md) [G24](../growth/24-result-before-signup.md)

## ねらい

有料機能を1回だけ丸ごと無料で体験させる。特に相性詳細（[M15](15-pair-compatibility-detail.md)）は
「読んでみないと価値が分からない」種類の商品なので、説明文を厚くするより1回配る方が効く。
配る対象は最も刺さる1面に絞る。全機能を1回ずつ配ると価値が薄まる。

**[M07](07-trial-7day.md) との境界**: あちらは月額（期間）の体験、こちらは単発機能の1回体験。
配る単位が違う（日数 vs チケット）ので、同じユーザーに両方渡ってもよい。

## 実装

**backend**

- [M04](04-ticket-credits.md) の台帳に `reason="first_free"` で1枚付与するだけにする。
  専用の「無料枠」概念を作らない。消費経路が1本に保たれ、集計もそのまま効く。
- 付与契機はユーザー作成時（`app/services/auth/`）。
  既存ユーザーへの一括付与はマイグレーションではなく管理コマンドで行う。
- 二重付与防止は `(user_id, reason)` の一意制約で担保する。
  アプリ側の条件分岐に頼ると、同時リクエストで2枚出る。

**frontend**

- 未使用時のラベルを「無料で1回見る」にし、価格を見せない。
  ここで金額を出すと、無料であることが伝わる前に離脱する。
- 使用後は残枠0であることと通常価格を同じ画面に出す（アンカーとして働く。[M28](28-price-anchoring.md)）。
- ja/en 同時。

## 検証

- 同一ユーザーの並行登録リクエストで2枚付与されないこと。
- 使用済みユーザーが再度無料で通らないこと。
- 台帳に `first_free` の付与と消費が両方残ること。
