# M34 検索フィルタ解放

親: [マネタイズ設計](../../monetization.md) 視点34 ／ 関連: [M31](31-per-target-billing.md) [M26](26-three-tier-pricing.md)

## ねらい

`CandidateFilter.tsx` の絞り込みを、有料で拡張する。
このプロダクト固有の目玉は**命式によるフィルタ**
（「日干が甲の人」「五行の水が強い人」「自分と相性70点以上」）。
年齢・距離だけなら他アプリと同じで払う理由が無いが、
相性でフィルタできるのはここにしかない。

## 実装

**backend**

- `app/api/routes/matching.py` に相性スコアによる絞り込みを追加する。
  **全候補との相性を都度計算すると重い**。日干・月支など粗い特徴を
  `app/models/profile.py` に非正規化して持ち、まず SQL で粗く絞ってから
  `compatibility.py` で精算する二段構えにする。マイグレーション必須。
- 非正規化した特徴は、プロフィールの生年月日更新時に必ず再計算する。
  ずれるとフィルタ結果が嘘になる。更新経路を1本に絞る。
- 無料でも相性の高い順の並び替えは提供する。
  並び替えまで有料にすると、無料ユーザーの体験が他アプリ以下になる。

**frontend**

- `CandidateFilter.tsx` に有料フィルタをグレーアウトで**見せる**。
  存在を隠すと課金動機にならない（[M01](01-free-paid-line.md) と同じ原則）。
- ja/en 同時。十干・五行の名称は既存の `features/fortune/terms.ts` を再利用する。

## 検証

- 非正規化フィールドと `pillars.py` の計算結果が常に一致すること
  （プロフィール更新後の再計算テスト）。
- フィルタ有無で候補集合が矛盾しないこと。
- 大量候補時の応答時間を計測して記録する。
