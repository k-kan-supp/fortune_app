# M36 リワード動画広告

親: [マネタイズ設計](../../monetization.md) 視点36 ／ 関連: [M04](04-ticket-credits.md) [M06](06-first-free.md)

## ねらい

無料層を収益化する。ただし**広告を先に入れると有料転換が落ちる**。
[M01](01-free-paid-line.md)〜[M35](35-verified-badge.md) が回り始めてからで良い、
というのが [monetization.md](../../monetization.md) の優先順位。
入れるなら「動画を見るとチケット1枚」のリワード型に限定し、
バナーやインタースティシャルは入れない。体験を削って単価も安い。

## 実装

**frontend**（広告 SDK はフロント側）

- 広告 SDK は Web/アプリで実装が分かれる。まず Web で1面だけ試す。
- 発火は**ユーザーが明示的に選んだときだけ**。自動再生しない。
- 視聴完了の検証をサーバ側で行う。クライアントの完了通知だけで報酬を出すと、
  すぐに偽装される。

**backend**

- `app/services/billing/rewards.py` に SDK の Server-Side Verification を受ける口を作る。
  署名検証を必ず実装し、検証済みのみ [M04](04-ticket-credits.md) の台帳に `reason="ad_reward"` で付与。
- 1日あたりの上限を設ける。無制限だと有料商品の価値が消える。
- 課金ユーザーには広告を一切出さない。`entitlement.py` で判定する。

## 検証

- 署名なしの報酬要求が拒否されること。
- 1日上限を超えて付与されないこと。
- 課金ユーザーに広告面が出ないこと。

## 完了条件

- [ ] サーバ側検証が実装されている
- [ ] 日次上限がある
- [ ] 課金ユーザーに広告が出ない
- [ ] 自動再生の広告が無い
- [ ] `check.sh` 緑
