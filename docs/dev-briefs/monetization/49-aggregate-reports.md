# M49 統計レポート

親: [マネタイズ設計](../../monetization.md) 視点49 ／ 関連: [M46](46-b2b-team-fit.md) [M45](45-bridal-ads.md)

## ねらい

「日干別のマッチング傾向」のような集計データをレポートとして売る。
**個票（個人単位のデータ）は絶対に売らない**。売るのは集計値のみで、
これは倫理の問題であると同時に、個人情報保護法上の第三者提供の問題でもある。
実装の主眼は「再識別できない粒度を機械的に保証すること」。

## 実装

**backend**

- `app/services/analytics/aggregate.py` を新設。集計クエリはここにのみ書く。
- **k-匿名性の下限を実装で強制する**。集計単位あたりの人数が閾値（例: k=50）未満なら、
  そのセルは出力しない。クエリを書く人が判断するのではなく、
  集計関数がその条件を満たさない結果を返せない構造にする。
- 出力可能な軸をホワイトリストで持つ。自由な軸の組み合わせを許すと、
  軸を重ねることで実質的に個人が特定できる（差分攻撃）。組み合わせ数にも上限を置く。
- 生年月日そのものを軸にしない。日干・五行など、多くの人が該当する粒度に丸める。
- レポート生成は非同期バッチ。リアルタイムの自由集計 API を作らない。

**frontend**

- 社内向けの生成画面のみ。外部への公開 UI は当面不要。

## 検証

- k 未満のセルが出力に含まれないこと（境界テスト k-1, k, k+1）。
- ホワイトリスト外の軸が拒否されること。
- 軸を最大数まで重ねても k 制約が守られること。
