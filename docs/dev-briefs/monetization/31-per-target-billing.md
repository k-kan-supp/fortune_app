# M31 相手ごとの課金単位

親: [マネタイズ設計](../../monetization.md) 視点31 ／ 関連: [M15](15-pair-compatibility-detail.md) [M04](04-ticket-credits.md)

## ねらい

相性詳細（[M15](15-pair-compatibility-detail.md)）を「機能への課金」ではなく
「相手1人あたりの課金」にする。**マッチが増えるほど収益が伸びる**構造になり、
プロダクトの成長と収益が同じ方向を向く。月額で見放題にすると、
最も価値のある瞬間（新しい相手が現れた瞬間）から対価が取れない。

## 実装

**backend**

- 購入単位は `(user_id, target_hash)`。`target_hash` は相手の生年月日時から作る安定ハッシュで、
  **相手のユーザー ID ではなく命式の同一性**で紐づける。
  相手が退会・再登録しても、同じ生年月日なら再購入させない。ここは誠実さの問題。
- 一度買った相手は永久に閲覧可（[M03](03-one-off-report.md) と同じ原則）。
- 消費は [M04](04-ticket-credits.md) のチケット。個別決済を挟まない。
- 月額上位プランには「月に何人まで」の枠を付ける。無制限にしない。
  無制限にした瞬間、この課金単位の意味が消える。

**frontend**

- `CandidateCard.tsx` / `CompatibilityModal.tsx` に購入済みバッジ。
  既に買った相手が一目で分かること。二重購入の不安が最大の摩擦。
- 購入前に相手の要約（無料の総合点）を必ず見せる。

## 検証

- 同一 `target_hash` への二重課金が起きないこと。
- 相手が退会後に再登録しても再購入を要求しないこと。
- 月枠の消費とリセットの境界。
