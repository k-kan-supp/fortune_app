# M23 鑑定履歴の保存

親: [マネタイズ設計](../../monetization.md) 視点23 ／ 関連: [G25](../growth/25-save-to-signup.md) [M02](02-subscription-daily.md)

## ねらい

「保存したい」は**会員化の最も自然な動機**（[G25](../growth/25-save-to-signup.md)）であり、
同時に解約の最大の抑止力になる。履歴が溜まったユーザーは辞めにくい。
機能としては地味だが、LTV への寄与は M シリーズで上位。

## 実装

**backend**

- `app/models/reading.py` を追加。`user_id` / `subject_label` / `birth_*` / `created_at`。
  **他人の生年月日を保存する**ことになるので、扱いを明示的に設計する:
  - 保存件数に上限を設ける（無料5件 / 有料50件）。無制限にすると名簿になる。
  - ユーザー削除時にカスケード削除。孤児レコードを残さない。
  - `subject_label` は自由入力（「母」「取引先のAさん」）。実名を要求しない。
  - マイグレーション必須。
- `GET /api/readings` / `DELETE /api/readings/{id}`。所有者以外は 404。
- 保存するのは入力値のみ。**鑑定結果は保存しない**。ロジック改善時に古い結果が残ると、
  同じ人の鑑定が2種類存在することになる。再計算は軽い。

**frontend**

- 結果画面に保存ボタン。未ログイン時はここでログインに誘導する（[G25](../growth/25-save-to-signup.md)）。
- 一覧はラベルで検索できるようにする。件数が増えると探せなくなる。
- ja/en 同時。

## 検証

- 上限超過時の挙動（古いものを消すのではなくエラーにして選ばせる）。
- ユーザー削除で履歴が確実に消えること。
- 他人の履歴 ID で 404 になること。
