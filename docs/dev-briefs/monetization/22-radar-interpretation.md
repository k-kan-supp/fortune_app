# M22 レーダー10枚の読み解き

親: [マネタイズ設計](../../monetization.md) 視点22 ／ 関連: [M01](01-free-paid-line.md) [G11](../growth/11-share-card-image.md)

## ねらい

`POST /api/fortune` は既にレーダーチャートを10枚返している。
図は出ているのに**読み方が無い**のが現状の最大の未収穫。
図をシェア素材として無料開放（[G11](../growth/11-share-card-image.md)）しつつ、
「なぜこの形になるのか」「この形の人はどう動くと良いか」を有料にする。
新規計算ゼロで作れる最も費用対効果の高い有料商品。

## 実装

**backend**

- `app/services/saju/analysis.py` の各チャートに解釈生成を追加する
  ── ただし `analysis.py` 本体は数値算出に留め、解釈は `narrative.py` 側に置く。
  責務を混ぜると、チャートを増やすたびに両方を触ることになる。
- 10枚それぞれについて「突出した軸」「へこんだ軸」「全体の形」の3観点で `body_code` を出す。
  形の分類（尖った形・平坦・偏った形）を先に定義してから文言を書く。
  軸ごとに個別の文を書くと10枚 × 軸数で破綻する。
- チャートは全て同じ形（`key` / `max_value` / `axes`）なので、
  **1つの汎用解釈器で10枚とも賄う**。これが設計の要点。

**frontend**

- `features/fortune/components/ChartCard.tsx` に解説の折りたたみを追加。
  `AnalysisCharts.tsx` の一覧は無料のまま。
- ja/en 同時。

## 検証

- 10枚すべてに解釈が出ること（`key` の網羅テスト）。
- 全軸が同値（完全な平坦）のときに「突出した軸」が空にならないこと。
- チャートを1枚追加したときに、解釈側の変更なしで動くこと。
