# M27 松竹梅（中央誘導）

親: [マネタイズ設計](../../monetization.md) 視点27 ／ 関連: [M26](26-three-tier-pricing.md) [M28](28-price-anchoring.md)

## ねらい

3段（[M26](26-three-tier-pricing.md)）のうち中央を選ばせる。
中央が最も利益率と満足度のバランスが良い設計にした上で、
**中身の差で選ばせる**。「おすすめ」バッジだけ付けて中身が同じなら、それは誘導ではなく騙し。
最上位は「本気の人向け」として実際に厚くする必要がある。

## 境界

段数と価格の定義は [M26](26-three-tier-pricing.md) が持つ。
この指示書が持つのは**プラン間の機能差**。
「3段にする」と「中央を選ばせる」を別作業として扱わないと、
両方が `catalog.py` を書き換えて衝突する。

## 実装

**backend**

- `catalog.py`（[M26](26-three-tier-pricing.md)）の各プランに `recommended: bool` を持たせる。
  フロントのハードコードにしない。A/B（[G33](../growth/33-ab-testing.md)）で
  推奨位置を動かせるようにするため。
- 上位プランには実際に機能を足す。最上位に年運（[M13](13-luck-cycles.md)）、
  中位に日次全文とテーマ別鑑定1本、下位に日次要約のみ、という具合に
  **機能コード集合で差が付いている**ことをテストで担保する。

**frontend**

- 中央を視覚的に大きく、他より上にずらす。
- 上位との差分を「+ 年運」のように加算で見せる。全機能を再掲すると差が埋もれる。
- 「おすすめ」の根拠を1行添える（「日次を毎日読む人はこちら」）。
  根拠の無いバッジは不信感になる。
- ja/en 同時。

## 検証

- 3プランの機能集合が真に包含関係（下位 ⊂ 中位 ⊂ 上位）になっていること。
  包含が崩れると「上位にしたら使えなくなった機能がある」という事故が起きる。
- `recommended` が2つ以上立たないこと。
