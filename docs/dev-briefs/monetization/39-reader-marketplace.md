# M39 鑑定士マーケット

親: [マネタイズ設計](../../monetization.md) 視点39 ／ 関連: [M38](38-reader-referral.md) [M40](40-take-rate.md)

## ねらい

占い師が出店し、ユーザーが個別鑑定を買う場を作る。
[M38](38-reader-referral.md) の送客で需要が確認できてから着手する。
**プロダクトの性格が変わる**（自社商品の販売 → 場の運営）ので、
決済・紛争処理・審査という運営コストが一気に増える。順番を飛ばさない。

## 実装

**backend**

- `app/models/reader.py`（出店者）と `app/models/booking.py`（予約）を追加。マイグレーション必須。
- **エスクロー**にする。鑑定完了まで代金を預かり、完了後に出店者へ渡す。
  即時送金にすると、未提供のまま逃げられたときに返金原資が無い。
- 出店審査を通す仕組みを先に作る。誰でも出店できる状態で開けると、
  質の低い鑑定でプロダクト全体の信用が落ちる。
- 紛争時の返金フローを実装してから公開する。運用で吸収する前提にしない。
- 出店者への支払いは特定商取引法・資金決済法の扱いを確認してから設計する。
  **ここは法務確認が先**で、実装はその後。

**frontend**

- 出店者一覧・予約・完了報告の3画面。
- 出店者のプロフィールに実績と得意分野。星評価は初期は入れない
  （母数が少ないと1件の低評価で出店者が消える）。
- ja/en 同時。

## 検証

- 未完了の予約で出店者に送金されないこと。
- 返金後に二重返金が起きないこと。
- 審査未通過の出店者が一覧に出ないこと。
