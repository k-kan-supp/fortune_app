# M46 B2B チーム相性

親: [マネタイズ設計](../../monetization.md) 視点46 ／ 関連: [M21](21-family-compatibility.md) [M47](47-public-api.md)

## ねらい

`compatibility.py` を法人向けに転用し、チーム編成の参考情報として売る。
単価は個人向けの数十倍。ただし**採用や人事評価に使われると差別につながる**。
生年月日による選別は、国や地域によっては違法になり得る。
「配属の参考」「関係構築のヒント」に用途を限定し、
採否判断への利用を契約と実装の両方で排除する。

## 実装

**backend**

- **独立した API 経路を作らない**。[M47](47-public-api.md) の
  `app/api/routes/public/v1/` に組織スコープを足す形で提供する。
  B2B 用に別の公開経路を立てると、認証・レート制限・バージョニングが二重になる。
  組織単位の認証と使用量計測も M47 の仕組みをそのまま使い、
  この指示書が持つのは**用途制限と同意管理**だけ。マイグレーションは組織スコープ分のみ。
- **出力に順位付けやスコアの序列を含めない**。
  「Aさんが最も適任」という出力を作らない。相互の関係性の記述に留める。
  ここは実装で担保する（ソート済みリストを返す API を作らない）。
- 被評価者本人の同意記録を必須にする。同意の無い個人の生年月日を
  組織が投入できる設計にしない。同意なしのレコードは計算を拒否する。
- 利用目的の宣言を API キー発行時に必須項目にする。

**frontend**

- 管理画面は最小限（キー発行、利用状況）。分析 UI は後回しで良い。

## 検証

- 同意記録の無いメンバーで計算が拒否されること。
- 出力に序列（順位・上位N件）が含まれないこと。
- B2B スコープのキーで、スコープ外のエンドポイントが叩けないこと。
