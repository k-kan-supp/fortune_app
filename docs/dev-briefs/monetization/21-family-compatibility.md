# M21 家族・親子相性

親: [マネタイズ設計](../../monetization.md) 視点21 ／ 関連: [M15](15-pair-compatibility-detail.md) [G23](../growth/23-group-reading.md)

## ねらい

相性ロジック（`compatibility.py`）を恋愛以外に転用する。
親子・きょうだい・職場は**マッチングに興味が無い層**にも刺さり、
既存の計算資産をそのまま使える。「子どもが何を考えているか分からない」は
恋愛相性より切実な需要で、単価も通る。

## 実装

**backend**

- `compatibility.py` に `relation` パラメータ（`romantic` / `parent_child` / `sibling` / `work`）を追加。
  **スコアは同じで、解釈だけ変える**。関係ごとにスコアリングを分けると検証不能になり、
  `test_compatibility.py` の期待値も維持できなくなる。
- 親子は方向性がある（親→子と子→親で読みが違う）ので、順序を保持した入力にする。
  恋愛相性は対称でよいが、ここは非対称。
- 「合わない」で終わらせない。関係を切れない相手なので、
  対処法（距離の取り方、伝え方）を必ず出力に含める。

**frontend**

- マッチング機能とは独立した入口にする。`FortunePage.tsx` 側に置く。
  マッチングの文脈に家族を混ぜると気味が悪い。
- 相手の生年月日を手入力する形式（プロフィール連携なし）。
- ja/en 同時。

## 検証

- **`test_compatibility.py` の既存期待値が変わらないこと**（CLAUDE.md の規約）。
  スコアに手を入れていないことをこのテストで担保する。
- 親→子と子→親で出力が異なること。
- 同一人物同士でエラーにならないこと。
