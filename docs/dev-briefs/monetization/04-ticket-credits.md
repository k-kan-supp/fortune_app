# M04 チケット従量

親: [マネタイズ設計](../../monetization.md) 視点4 ／ 関連: [M05](05-hybrid-billing.md) [M31](31-per-target-billing.md)

## ねらい

「相性を1回見る」「鑑定書を1通出す」を共通のチケットで払えるようにする。
商品ごとに決済を挟むと購入のたびに離脱するので、**まとめ買い＋その場で消費**にして
2回目以降の摩擦をゼロにする。

## 実装

**backend**

- `app/models/credit.py` に台帳方式で持つ。残高カラムを直接更新しない。
  `credit_ledger(user_id, delta, reason, ref_id, created_at)` を追加し、残高は合計で求める。
  障害時の追跡と返金がこの方式でないと破綻する。マイグレーション必須。
- `app/services/billing/credits.py` に `grant()` / `consume()` を置く。
  `consume()` は残高チェックと挿入を**同一トランザクション**で行い、
  行ロックで同時実行による残高割れを防ぐ。
- 消費理由は enum で管理（`compat_detail` / `report` / `like_pack` …）。
  文字列を散らすと後で集計できない。
- `GET /api/credits` で残高と直近の増減を返す。

**frontend**

- ヘッダー（`components/layout/`）に残高を常時表示。持っていることを忘れさせない。
- 消費前に必ず確認を1枚挟む。無言で減ると信用を失う。
- ja/en 同時。

## 検証

- 並行 `consume()` で残高がマイナスにならないこと（同時実行テスト）。
- 台帳の合計と表示残高が常に一致すること。
- 付与・消費・返金の3系統それぞれのテスト。
