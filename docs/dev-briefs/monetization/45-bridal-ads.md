# M45 ブライダル広告枠

親: [マネタイズ設計](../../monetization.md) 視点45 ／ 関連: [M44](44-shrine-collab.md) [G44](../growth/44-marriage-agencies.md)

## ねらい

マッチングが成立し、関係が続いているユーザーは**ブライダル業界にとって最も価値の高い層**。
広告単価が全カテゴリで最上位クラスになる。
ただし、ここは**個人データの取り扱いを最も誤りやすい**面でもある。
「交際が進んでいそうな人」を推定して広告主に渡すような設計は絶対に作らない。

## 実装

**backend**

- **広告主にユーザーデータを渡さない**。掲載は自社面のみで、
  ターゲティングも自社内で完結させる。外部の広告 SDK に行動データを流さない。
  これが本指示書の最重要点。
- 掲載条件は粗い属性（年齢帯・地域）に留め、マッチング状況やチャット内容を条件に使わない。
  チャット本文を広告に利用する経路をコード上に作らない。
- `app/services/commerce/placements.py` に掲載枠を定義。
  掲載実績の集計は匿名の合計値のみ（[M49](49-aggregate-reports.md) と同じ規律）。

**frontend**

- 掲載場所は限定する。チャット画面（`ChatWindow.tsx`）には出さない。
  会話の場に広告を挟むと体験が壊れる。
- 広告である旨を明示。
- 広告を非表示にする設定（有料プラン）を用意する。
- ja/en 同時。

## 検証

- 外部へユーザー識別子が送出されないこと（ネットワーク経路の確認）。
- マッチング状況が掲載条件に使われていないこと。
- チャット画面に広告が出ないこと。
