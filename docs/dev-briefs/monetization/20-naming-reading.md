# M20 命名

親: [マネタイズ設計](../../monetization.md) 視点20 ／ 関連: [M03](03-one-off-report.md) [M25](25-print-fulfillment.md)

## ねらい

赤ちゃんの名付け。**単価が最も高い**（数千〜万円）テーマ別鑑定で、
一生に数回しか発生しないぶんサブスクには向かず、
都度課金（[M03](03-one-off-report.md)）＋製本（[M25](25-print-fulfillment.md)）と相性が良い。
生年月日時が確定している（出生後）ので、命式は正確に出せる。

## 実装

**backend**

- `app/services/saju/readings/naming.py`。命式の五行の不足を補う字を提案する構成にする。
- **漢字の画数データが必要**。これが最大の実装コスト。
  旧字体・新字体で画数が変わる流派差があるので、採用する流派を1つ決めて明記する。
  複数流派に対応しようとすると答えが割れて商品にならない。
- 人名用漢字の範囲を法令ベースで持つ。使えない字を提案したら商品として成立しない。
  データは `app/services/saju/readings/data/` に置き、出典と更新日をファイル冒頭に書く。
- 出力は「補うべき五行」「適した音の傾向」「候補字」。名前そのものを断定しない。
  最終決定は親がするもので、提案の域を出ない設計にする。

**frontend**

- 候補字に読み・画数・意味を併記。
- 入力は出生日時＋姓。姓の画数が計算に要る。
- ja/en 同時。ただし英語圏に漢字命名の需要は薄いので、en は説明中心で良い。

## 検証

- 人名用漢字外の字が提案に出ないこと（全候補の走査テスト）。
- 旧字体・新字体で画数が一貫していること。
- 画数データの件数がテストで固定されていること（欠損の検知）。

- [ ] 人名用漢字外が出ない
