# M37 開運グッズ提携

親: [マネタイズ設計](../../monetization.md) 視点37 ／ 関連: [M43](43-merch.md) [M18](18-health-reading.md)

## ねらい

鑑定結果に紐づけて商品を紹介し、送客手数料を得る。
命式から「補うべき五行」が出る（[M18](18-health-reading.md) と同じ材料）ので、
色・素材・石などを機械的に対応付けられる。在庫も物流も持たない点が
[M43](43-merch.md) との違いで、着手コストが低い。

## 実装

**backend**

- `app/services/commerce/affiliate.py` に商品カタログと五行の対応を持つ。
  対応表はデータとして持ち、コードに埋めない。提携先が変わるたびに改修になる。
- リンクにトラッキング ID を付与する経路を1本に絞る。
  各所で URL を組み立てると、計測漏れと ID の付け忘れが必ず起きる。
- **広告・アフィリエイトである旨の表示（ステマ規制対応）を実装で強制する**。
  リンクを出力する関数が必ず表示ラベルを伴う型を返すようにし、
  表示を省略できない構造にする。運用の注意喚起ではなく型で守る。

**frontend**

- 鑑定本文の中に紛れ込ませない。「PR」ラベル付きの独立ブロックにする。
  本文と広告の区別が付かない配置は、規制上も体験上も悪手。
- 有料鑑定の中には出さない。金を払った先に広告が出るのは最悪の体験。
- ja/en 同時。

## 検証

- リンク出力時に PR ラベルが必ず伴うこと（型・テストで担保）。
- 有料鑑定のレスポンスにアフィリエイトブロックが含まれないこと。
- トラッキング ID が全リンクに付くこと。
