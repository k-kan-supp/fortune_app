# M10 学割

親: [マネタイズ設計](../../monetization.md) 視点10 ／ 関連: [G46](../growth/46-campus.md) [M26](26-three-tier-pricing.md)

## ねらい

占いもマッチングも10代後半〜20代前半の可処分所得が薄い層に強い需要がある。
学割は単価を下げる代わりに**母数と口コミ**を取りにいく施策で、
[G46](../growth/46-campus.md) の学園祭・大学施策とセットで初めて費用対効果が合う。

## 実装

**backend**

- 学生判定は自前で審査しない。学生証画像の目視確認は運用が破綻する。
  外部の学生認証サービスか、`ac.jp` ドメインのメール確認に限定する。
  後者なら `app/services/auth/` の既存メール確認フローをそのまま再利用できる。
- `app/models/user.py` に `student_verified_until`（日付）を持たせる。
  永久フラグにしない。**卒業後も学割のまま残る**のが最大の損失要因。マイグレーション必須。
- 期限の3週間前に再確認を促す通知を積む。
- 割引は [M09](09-pair-plan.md) と同じくプロバイダのクーポンで表現する。

**frontend**

- 申請は設定画面に置き、購入フローの中に挟まない。決済直前に審査待ちが発生すると全部落ちる。
- 「審査中でも通常価格で今すぐ使え、承認後に差額を次回請求で調整」を明示する。
- ja/en 同時。en 側は日本の学校ドメイン前提の文言にしない。

## 検証

- `student_verified_until` 経過後、次回更新から通常価格になること。
- 期限切れユーザーが学割価格で決済できないこと。
- 学生メール以外のドメインが弾かれること。

## 完了条件

- [ ] 学生資格に期限がある
- [ ] 期限切れが自動で通常価格に戻る
- [ ] 審査が購入フローを止めない
- [ ] `check.sh` 緑
