# M50 ギフト購入

親: [マネタイズ設計](../../monetization.md) 視点50 ／ 関連: [M03](03-one-off-report.md) [G20](../growth/20-referral-reward.md)

## ねらい

鑑定書（[M03](03-one-off-report.md)）を他人に贈れるようにする。
**購入者と利用者が別**になるので、新規ユーザーが「既に対価が払われた状態」で
入ってくる ── 課金と集客が同時に起きる。誕生日プレゼントの文脈と相性が良く、
[G49](../growth/49-birthday-coupon.md) と組み合わせると季節性に依存しない需要が作れる。

## 実装

**backend**

- `app/models/gift.py`。`purchaser_id` / `code` / `product_code` / `redeemed_by` / `expires_at`。
  マイグレーション必須。
- ギフトコードは推測不能な長さにする。短いコードは総当たりで引かれる。
  引き換え試行にレート制限をかける。
- **贈る側が受け取る側の生年月日を知らないケースが普通**。
  購入時に対象者情報を求めず、受け取った人が自分で入力する形にする。
  ここを間違えると「相手の生年月日を知らないと贈れない」商品になり、ほぼ売れない。
- 未使用のまま期限切れになった分の扱い（返金するか失効か）を規約で決めて実装する。
  資金決済法上の前払式支払手段に該当し得るので、有効期限の設定は法務確認を経る。
- 引き換えは1回限り。トランザクションで担保する。

**frontend**

- 贈る側にはメッセージカードの体裁を用意する。コードだけ渡す体験は贈り物にならない。
- 受け取り画面は未ログインでも見られるようにし、引き換え時に登録させる
  （[G24](../growth/24-result-before-signup.md) と同じ順序）。
- ja/en 同時。

## 検証

- 同一コードの二重引き換えが起きないこと（並行テスト）。
- 引き換え試行のレート制限が効くこと。
- 期限切れコードが引き換えられないこと。

## 完了条件

- [ ] 相手の生年月日なしで購入できる
- [ ] 二重引き換えが起きない
- [ ] 有効期限の扱いが法務確認済み
- [ ] `check.sh` 緑
