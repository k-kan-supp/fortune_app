# M30 提示タイミング

親: [マネタイズ設計](../../monetization.md) 視点30 ／ 関連: [M29](29-paywall-placement.md) [G32](../growth/32-funnel-analytics.md)

## ねらい

[M29](29-paywall-placement.md) が「どこで」なら、こちらは「いつ」。
命式を出した直後の関心は数十秒で落ちる。**結果表示から離脱するまでの間**に
提示できるかが全て。ただし表示と同時にモーダルを被せるのは逆効果で、
結果を読ませてから出す。読む前に売ると、何を売られているか分からない。

## 実装

**frontend**（この指示書はフロント主体）

- 提示のトリガーを複数用意し、最初に発火したもので出す:
  - 有料ブロックの見出しが画面内に入った（Intersection Observer）
  - 結果画面に滞在30秒
  - 有料ブロックのぼかし部分をタップした
- モーダルではなくインライン（`ResultSummary.tsx` の流れの中）を第一候補にする。
  モーダルは閉じられて終わる。
- 一度閉じたら同一セッションで再表示しない。追いかけると嫌われる。
  再訪時はリセットする。
- 発火トリガーと結果（購入 / 閉じる / 離脱）を [G34](../growth/34-analytics-foundation.md) に送る。

**backend**

- 提示の設定値（滞在秒数、トリガーの有効/無効）を `GET /api/config` で配信する。
  フロントに埋め込むと調整のたびにビルドが要る。

## 検証

- 3トリガーがそれぞれ単独で発火すること。
- 同一セッションで二重表示されないこと。
- トリガーごとの発火数と転換がイベントで分解できること。
