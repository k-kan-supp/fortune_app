# M35 認証バッジ

親: [マネタイズ設計](../../monetization.md) 視点35 ／ 関連: [M10](10-student-plan.md) [M33](33-read-receipts.md)

## ねらい

本人確認済みバッジ。マッチングでは**信頼が最大の摩擦**で、
バッジは相手側の安心を買う商品になる。ただし本人確認そのものを有料にするのは
安全性を売ることになり筋が悪い。**本人確認は無料で提供し、
バッジの表示や優先表示を有料にする**という切り分けにする。

## 実装

**backend**

- 本人確認は外部の eKYC サービスに委ねる。身分証画像を自前で保持しない。
  `uploads/` に身分証が残る構成は絶対に作らない。
  `app/services/verification/` を新設し、外部サービスの結果（可否と確認日時）だけを保存する。
- `app/models/user.py` に `identity_verified_at` を追加。画像・書類番号は持たない。マイグレーション必須。
- 有料にするのは表示の優先度（`DiscoverPage` の上位表示）に留める。
  未確認ユーザーを機能的に締め出す設計は、無料層の体験を壊す。
- 確認済み同士に限定した絞り込みは**無料**で提供する。安全に関わる機能を課金にしない。

**frontend**

- `CandidateCard.tsx` / `ProfilePage.tsx` にバッジ表示。
- 「バッジ＝安全の保証ではない」旨の注記を入れる。過信を招く表示にしない。
- ja/en 同時。

## 検証

- 身分証画像がサーバに保存されないこと（保存経路が存在しないことを確認）。
- 確認済みフィルタが無料で使えること。
- 確認取り消し時にバッジが即時に消えること。
