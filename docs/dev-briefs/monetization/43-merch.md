# M43 お守り・カレンダー物販

親: [マネタイズ設計](../../monetization.md) 視点43 ／ 関連: [M14](14-lucky-day-calendar.md) [M25](25-print-fulfillment.md) [M44](44-shrine-collab.md)

## ねらい

開運日カレンダー（[M14](14-lucky-day-calendar.md)）を**紙のカレンダー**にする。
自分の命式に基づく個別のカレンダーは既製品には存在しない商品で、
年末の季節需要（[G47](../growth/47-new-year-season.md)）と噛み合う。
お守り類は在庫リスクがあるので、まずカレンダー（オンデマンド印刷）から。

## 実装

**backend**

- 生成は [M24](24-pdf-export.md) の PDF 基盤を再利用する。
  1〜12月の各月に、その人の四領域の日次評価を刷り込む。
  365日分の計算は [M14](14-lucky-day-calendar.md) の `range_reading()` をそのまま使う。
- 配送・注文管理は [M25](25-print-fulfillment.md) の `fulfillment/` を再利用。
  住所の保持期限もそちらの規律に従う。**ここで新しい住所テーブルを作らない**。
- 受注期限を設ける。年末商品なので、印刷会社の締切から逆算した締切を持つ。
  締切をコードに埋めず設定にする。

**frontend**

- プレビューを必ず出す。自分の名前と命式が入る商品なので、
  現物を見ずに買わせると返品要求が出る。
- 納期と受注締切を購入前に明示。
- ja/en 同時。

## 検証

- 365日分の生成が現実的な時間で終わること（計測して記録）。
- 節入り・年またぎの日が正しく処理されること。
- 締切後に注文できないこと。
