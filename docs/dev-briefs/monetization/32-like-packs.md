# M32 いいね追加購入

親: [マネタイズ設計](../../monetization.md) 視点32 ／ 関連: [M04](04-ticket-credits.md) [M34](34-premium-filters.md)

## ねらい

マッチングアプリの標準的な消費財。ただし**このプロダクトでは主役にしない**。
いいね課金は「量で押す」使い方を促し、相性で選ぶという本来の価値と衝突する。
無料枠を十分に出した上で、足りない人向けの補助に留める。
主収益は相性詳細（[M31](31-per-target-billing.md)）側に置く。

## 実装

**backend**

- `app/models/matching.py` に日次のいいね枠を追加。
  無料枠は1日10〜15程度から始める。少なすぎるとマッチが成立せず、
  プロダクトそのものが死ぬ。ここをケチると全部の指標が落ちる。
- 追加分は [M04](04-ticket-credits.md) のチケットで購入。専用通貨を作らない。
- 日次リセットは JST の固定時刻。ユーザーごとの24時間ロールにしない
  （いつ回復するか分からない設計は苦情になる）。
- 相性スコアが高い相手へのいいねは枠を消費しない、という設計も検討する。
  プロダクトの主張（相性で選ぶ）と課金が一致する。

**frontend**

- 残枠と回復時刻を `DiscoverPage.tsx` に常時表示。
- 枠切れ時に購入を出す。それ以外の場面では出さない。
- ja/en 同時。

## 検証

- 日次リセットの境界（JST 深夜、夏時間の無い前提を明記）。
- 枠がマイナスにならないこと（並行リクエスト）。
- 購入分と無料枠の消費順序（無料枠から先に消費）。
