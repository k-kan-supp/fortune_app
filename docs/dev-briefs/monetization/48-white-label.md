# M48 ホワイトラベル

親: [マネタイズ設計](../../monetization.md) 視点48 ／ 関連: [M47](47-public-api.md) [M45](45-bridal-ads.md)

## ねらい

結婚相談所や占いサイトに、自社ブランドで四柱推命機能を提供する。
[M47](47-public-api.md) が「部品を売る」なら、こちらは「画面ごと売る」。
単価は最も高いが、**カスタマイズ要求が青天井になる**のが最大のリスク。
どこまで変えられるかを最初に線引きし、それ以外は受けない体制で始める。

## 実装

**frontend**

- 変更可能な範囲を**テーマ変数に限定**する。`styles/` の CSS 変数で
  配色・ロゴ・フォントだけを差し替え可能にし、レイアウトの個別対応は受けない。
  ここを緩めると1社ごとに分岐が増えてコードが維持不能になる。
- テナント判定はドメインで行い、ビルドを分けない。
  テナントごとにビルドすると、本体の改修が全テナントへの再デプロイになる。

**backend**

- `app/models/tenant.py`（テナント設定）。マイグレーション必須。
- **データはテナントごとに完全分離**する。全クエリにテナント境界を強制する仕組みを入れ、
  個別のクエリで `WHERE tenant_id` を書き忘れても漏れない構造にする。
  ここが漏れると他社の顧客データが混ざる ── 事業が終わる規模の事故になる。
- 文言の差し替えは `core/i18n.py` の `MESSAGES` をテナントで上書きできる形にする。

## 検証

- **テナント間のデータ分離テストを最優先で書く**。
  テナント A のキーでテナント B のデータが1件も取れないこと。
- テーマ変数以外の変更が効かないこと。
- テナント追加が設定のみで完結すること。
