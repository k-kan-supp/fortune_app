# マネタイズ設計（50視点）

集客側は [growth.md](growth.md)。この2本で「100視点」の整理になっている。

前提は現在のプロダクト構成 — 四柱推命の命式算出（`services/saju/`）＋相性判定
（`compatibility.py` / `species_compat.py`）＋毎日の運勢（`daily.py`）＋マッチングとチャット。
つまり **「単発の鑑定」と「継続する関係」の両方に課金点がある**のが特徴で、
占いアプリ単体ともマッチングアプリ単体とも違う設計ができる。

## 1. 課金の形（1–10）

| # | 視点 | 中身 |
| --- | --- | --- |
| 1 | 無料/有料の線引き | 命式は無料、解釈が有料 |
| 2 | サブスク | 月額で毎日の運勢を開放 |
| 3 | 都度課金 | 鑑定書を1通ずつ販売 |
| 4 | 従量 | チケット制（1回=1消費） |
| 5 | ハイブリッド | 月額＋都度の併用 |
| 6 | 初回無料枠 | 1回だけ全開放 |
| 7 | トライアル | 7日間 |
| 8 | 年額割 | 2ヶ月分無料相当 |
| 9 | ペア割 | 2人同時加入で割引 |
| 10 | 学割 | 若年層の入口 |

命式そのもの（干支・十神・十二運の表）は**無料で出し切る**。ここは検索流入の資産
（[growth.md](growth.md) の 1–10）であり、囲うと集客が死ぬ。売るのは「その表が
自分にとって何を意味するか」＝ `narrative.py` の出力側。

（[growth.md](growth.md) 21–25）。ここを最優先で設計する。

## 3. 価格と提示の設計（26–35）

| # | 視点 | 中身 |
| --- | --- | --- |
| 26 | 3段構成 | 480 / 980 / 1980 円 |
| 27 | 松竹梅 | 中央に誘導 |
| 28 | アンカー | 最上位を先に見せる |
| 29 | ペイウォール位置 | 最も刺さる一文の直前 |
| 30 | タイミング | 結果表示の直後 |
| 31 | 課金単位 | 相性は相手ごと |
| 32 | 消費財 | いいね追加購入 |
| 33 | 可視化 | 既読・足あと解放 |
| 34 | 探索 | 検索フィルタ解放 |
| 35 | 信用 | 認証バッジ |

29 が最大の変数。命式を出した直後の「もっと知りたい」が最も高く、
時間が経つと急落する。`ResultPage` の初回表示から数秒以内に提示できるかで
転換率が変わるので、ここは A/B の対象にする（[growth.md](growth.md) 33）。

## 4. 収益源の拡張（36–50）

| # | 視点 | 中身 |
| --- | --- | --- |
| 36 | 広告 | 無料層にリワード動画 |
| 37 | 送客 | 開運グッズ提携 |
| 38 | 送客 | 占い師の個別鑑定へ |
| 39 | プラットフォーム | 鑑定士の出店 |
| 40 | 手数料 | 出店・決済の取り分 |
| 41 | イベント | オンライン鑑定会 |
| 42 | 継続 | コミュニティ月額 |
| 43 | 物販 | お守り・カレンダー |
| 44 | コラボ | 神社仏閣 |
| 45 | 広告枠 | ブライダル |
| 46 | B2B | 配属・チーム相性 |
| 47 | B2B | API 提供 |
| 48 | B2B | ホワイトラベル |
| 49 | データ | 統計レポート（個票は販売しない） |
| 50 | 贈答 | 相性診断のギフト |

46–48 は `services/saju/` がフレームワーク非依存の純ロジックである
（[architecture.md](architecture.md)）ことが効く。HTTP 層を差し替えるだけで
外販形態を増やせる。

49 は**個人の生年月日・プロフィールを外部に出さない**ことが前提。
売るのは集計済みの傾向のみで、再識別可能な粒度には落とさない。

## 優先順位

1. **1・26・29** — 無料/有料の線引きと価格、そして提示位置。他は全部この上に乗る。
2. **15** — 相性課金。収益と拡散が同じ導線に乗る唯一の面。
3. **2・23** — 継続課金と履歴保存。LTV はマッチングの継続率に連動する。

36 以降は 1–35 が回り始めてからで良い。順番を逆にすると、
広告や提携が「本体が弱いことの埋め合わせ」になって単価が上がらない。
